Irrigation Control

AquaGrow can operate in AUTO or MANUAL mode. In AUTO mode, the Arduino decides when irrigation should start and stop using the configured soil moisture thresholds. MANUAL mode allows the user to send direct pump commands.

🤖 Operating Mode
AUTO allows threshold-based irrigation. MANUAL allows direct pump control.
Automatic mode:
When soil moisture reaches or falls below the dry threshold, the Arduino can activate irrigation. Once moisture reaches or exceeds the wet threshold, the pump can be stopped. Between the two thresholds, the previous pump state can be maintained to avoid unnecessary switching.

Manual mode:
The user controls the pump using the ON and OFF buttons. Manual control does not depend on the automatic threshold decision.

System Settings

Configure the moisture thresholds used by the Arduino's automatic irrigation logic. Values are checked before commands are sent.

⚙️ Irrigation Thresholds
Enter percentages between 0 and 100. The dry threshold should be lower than the wet threshold.

🔴 Dry Condition

Soil moisture at or below the dry threshold is treated as a dry condition.

🟢 Wet Condition

Soil moisture at or above the wet threshold is treated as a sufficiently wet condition.

🧠 Why Two Thresholds?

Using separate dry and wet thresholds creates a useful control gap between starting and stopping irrigation. This can reduce rapid ON/OFF switching when the measured moisture fluctuates around a single value.

About AquaGrow

AquaGrow is a smart irrigation project combining environmental awareness, agriculture and electronics. Its purpose is to use measured soil conditions to support more controlled and efficient irrigation.

🌱 Project Introduction

AquaGrow is a smart irrigation system designed to monitor soil moisture and environmental conditions and control a water pump according to soil requirements. The system combines a capacitive soil-moisture sensor, DHT22 temperature/humidity sensor, Arduino Uno, ESP32, relay and low-voltage DC water pump.

❗ Problem Identification

Conventional watering may provide more water than a plant currently requires or may depend entirely on manual observation. This can lead to inefficient water use, especially when watering decisions are not based on actual soil moisture.

🔬 Scientific Concept

Soil moisture sensors convert changes in soil moisture into an electrical signal that a microcontroller can measure. The Arduino processes the sensor reading and converts it into a useful moisture percentage. The DHT22 provides temperature and humidity information.

🧪 Methodology

  1. Measure soil moisture.
  2. Measure temperature and humidity.
  3. Process readings using Arduino.
  4. Determine soil condition.
  5. Apply automatic threshold logic.
  6. Control the relay and pump.
  7. Send live data to ESP32.
  8. Transfer information through USB.
  9. Display data in AquaGrow dashboard.

💡 Innovation

AquaGrow combines real-time sensing, automatic irrigation logic and a modern browser dashboard. The USB/Web Serial architecture also allows the dashboard to communicate locally without depending on an Internet connection or an ESP32 Wi-Fi hotspot.

🌍 Environmental Relevance

By linking irrigation decisions to soil moisture, the system encourages watering based on measured conditions rather than using a fixed watering routine. This supports responsible water management.

💧 Water Conservation

Automatic control can reduce unnecessary watering by stopping irrigation after the configured wet threshold is reached. The actual effectiveness depends on sensor calibration, threshold selection and the plant's environmental requirements.

📊 Findings / Results

The dashboard records live moisture readings and displays changes over time through the History section. This allows observations of soil conditions and pump behaviour during testing.

🚀 Future Scope

  • Multiple plant-zone monitoring.
  • Long-term sensor data storage.
  • Advanced plant-specific recommendations.
  • Weather-aware irrigation.
  • Mobile application integration.
  • Cloud synchronization as an optional future feature.
  • More advanced AI-based plant analysis.

🖥️ USB / Web Serial Architecture

🔗 Communication

Arduino ↔ ESP32 communication uses a dedicated serial connection at 57600 baud. The ESP32 communicates with the browser through USB at 115200 baud.

🌐 Browser

The dashboard uses the Web Serial API supported by compatible Chromium-based browsers such as Google Chrome and Microsoft Edge.

🚫 No Wi-Fi

This version does not create an ESP32 Wi-Fi hotspot, does not use 192.168.4.1 and does not require Internet connectivity for sensor communication.

⚡ Performance

The communication design uses non-blocking serial processing, rapid packet forwarding and automatic sensor updates without unnecessary long delays.
